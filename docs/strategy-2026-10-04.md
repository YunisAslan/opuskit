# Strategy discussion — where OpusKit is going (2026-10-04)

A record of the founder's and Claude's discussion after example #16 (QUM), and of the four research reports it led to.
Nothing here is decided yet; the open questions at the end are the user's to answer.

## 1. The question

The user (after QUM): "Let's stop and think. Where is OpusKit going? Can we make a product the market needs, at this
pace?"

Claude's honest read: the technical base is strong (a research-based library, a deterministic engine, ready sections and
effects, quality rules, 16 real example sites), but the last weeks went almost entirely into making the library and the
examples better. That does not answer whether anyone will use it or pay for it. Concerns:
1. **Who the user is is unknown.** Today's path — kit → download a zip → run Claude Code locally → a few prompts — is
   developer work. A developer often doesn't want a three-step design wizard; a non-developer can't walk this path.
2. **Only we have checked the results.** Every example was built with Claude's hands on it (photos, prompts, fixes taken
   back). Whether an ordinary user gets the same quality is unmeasured.
3. **The product around it is a mock** (auth, billing, storage), and the weakest part — first contact and the way from
   zip to a working site — got the least time.
4. **Platforms could add "style packs"**; the only lasting edge is the quality of the taste and how well it is packaged
   for agents — and that has to be proven.

## 2. Who could the user be

| Segment | What they want | Fit |
|---|---|---|
| A. Business owner, not a developer | A site live today, domain, hosting, editing later | Biggest market, hardest work: we would have to build and host for them; their complaints are support and domains, not looks |
| B. Designer without code | Their own design, full control | Weak today (the kit decides for them); strong second once agent-native |
| C. Developer, freelancer, small studio building client sites with AI agents | Speed plus the taste they lack; sites that don't look AI-made | Natural fit — Claude Code, Cursor and skills are their own tools |
| D. AI site platforms (B2B) | A "design taste" layer for their generation | Interesting, needs proof and a name first |

The user: "OpusKit wouldn't be a bad engine for C and D." Claude agreed: OpusKit already is an engine (knowledge base,
`composeRecipe`, Build Package adapters, ready code, `check` rules — almost all UI-independent TypeScript); `/kit` is one
interface on top. For C the door would be an MCP server / Claude Code plugin / `npx opuskit`; for D an API or npm
package. Missing: starting from a text brief instead of kit clicks, a separate versioned package, and proof.

## 3. "If it's a framework, sites will look the same"

The user: a fully framed OpusKit would be uninteresting, because people don't want their sites to look alike. How could
a strengthening change OpusKit's fate?

Claude's answer: turn it from a menu of options into a cook — rules, generators and a critic, with the catalogue only as
starting examples:
1. **Build from the brand's own material** — palette from the owner's photos, motif from the logo or product, voice from
   the brief (the colour research already has the fit algorithm). Two brands of the same kind get different sites.
2. **Parameters instead of fixed options** — generated palettes within the rules, type weight/size/width as parameters,
   sections composed from layout × media placement × tone × density. The moat is the rules, not the presets.
3. **A signature moment per brand** — the engine maps the brand's metaphor onto a mechanic (pin, scrub, drag, reveal, a
   travelling shape) and the agent builds it fresh.
4. **A critic** — screenshot the built site, check the rules, measure similarity to sites built before, send fixes back
   to the agent. A guarantee nobody else sells: "your site won't look like everyone else's".
5. **A data moat** — the award-site research as a corpus that keeps growing.

## 4. The store idea

The user: what if OpusKit is a store instead of a framed kit — lots of interesting things with pictures and videos
(sidebar menus, rotating text, brand cursor, reading line, beautiful loading, 3D image gallery…), the user puts what they
like in a cart and builds a site from them?

Claude: attractive as a front door, with two real risks. The market is full and mostly free (Aceternity, Magic UI, React
Bits, Motion Primitives, Cult UI, 21st.dev with its own MCP). And a cart of effects becomes "effects soup" — the award
research says one idea, one memorable moment per page. What would set it apart is a smart cart on top of the engine:
every item shown in your own brand, compatibility rules (one per slot, a limit on heavy effects, menu ↔ footer fit), the
engine fills in the rest so the result is one coherent site, export to the agent, and the critic.

## 5. Research: looking where the light isn't (four reports)

The user asked for a search outside our own approach — "the answer may be in the dark, not where the light is".

- `docs/research/2026-10-04-landscape-builders.md` — 23 products. Money is in hosted prompt-to-app tools (Lovable
  ~$400M ARR, Replit ~$525M, Bolt $40M in six months) that leave design to model defaults; Framer earns on design ($50M
  ARR, $6.5M paid to template creators in 2025). Anthropic names the sameness "distributional convergence". Five
  approaches: template + AI fill; structure first; bring your own design system (shadcn registries, Stitch's DESIGN.md);
  many directions side by side; clone a reference. Tools converge on a portable design spec. Gaps: a checked,
  distinctive look for people with no brand yet; award-style motion as clean-licence pieces for agents; checking the
  built site against the intended design.
- `docs/research/2026-10-04-analogies.md` — 12 patterns from outside web design. "Procedural oatmeal" (Kate Compton,
  Spore): things that differ on paper look the same to people; MIT Media Lab's 40,000-variant logo was dropped for this.
  The fields that solved it keep a curated, fixed structure and let something real from the owner drive the variable
  part. Transfers: seed from the owner's real material; a chess.com-style Site Review with a sameness meter; capped
  Designer Looks; shareable style codes; remix with credit; one checkable rule per site (Oulipo). Wild: a live identity
  driven by a data feed; selling exclusivity of a look.
- `docs/research/2026-10-04-demand.md` — 22% of 500 Show HN landing pages show four or more AI-design patterns. Visitors
  notice less than makers, so sell to makers. C (freelancers, studios) has the sharpest, most monetisable pain; B is a
  strong second (44% of designers vibe-code more than half their time); A's complaints are support and domains, not
  looks; D builds design quality in-house or acquires it. Free anti-slop rules are already popular (Anthropic's
  frontend-design 277k+ installs, Impeccable 15k+ stars): rules alone won't sell — a settled direction plus checked,
  ready code delivered inside the agent will. Tailwind's revenue fell ~80% because agents write the code and nobody
  visits the storefront. Top jobs: not look AI-made; a design the agent follows on every page; a client site in a day at
  agency quality; show the client before building; SEO, accessibility and spacing basics done right.
- `docs/research/2026-10-04-business-models.md` — a Baku site sells for 150–800 AZN, so local SMBs won't pay for
  award-level work. Fastest money: productised "award-level site in 72 hours" sold abroad (Designjoy ~$3.1M ARR, one
  founder) and white-label production for agencies. Biggest upside: a white-label site builder for banks, hosts and
  telcos (Duda, BaseKit; locally Birbank Biznes, PASHA/ABB, azhosting.az, KOBİA + IDDA). Also: open-core (free engine,
  paid library — Tailwind Plus, Aceternity Pro), a "Lighthouse for taste" score API, Framer/Shopify templates made by the
  engine, Anthropic's plugin directory (open to submissions since 2026-09-25). Direct free competitor: Impeccable.

## 6. Claude's synthesis

**Direction: a taste engine inside the agent**, for C first and B beside it:
1. **Directions** — 6–12 fully drawn directions from the brief and the brand's own material (photos, logo, name); pick
   one, or start from "like Sela Mor". Replaces the form and avoids oatmeal.
2. **Recipe and code inside the agent** — the recipe as a DESIGN.md, sections and effects as a shadcn registry, a Claude
   Code plugin. No zip.
3. **Site Review** — checks the built site, marks mistakes with fixes, shows a sameness meter. Built on `check`.

Money now: the 72-hour service and agency white-label (funds the product, makes real cases, tests OpusKit daily). Later:
Pro library, capped designer looks, white-label for banks/hosts/telcos. Stop: new example sites and library breadth.

## 7. Where the user landed: a library of designs

The user: "What interests me most are designs made with interesting layouts and filters, and the users who get them —
by adding to a cart, or copying them one by one."

Claude's proposal — **OpusKit Library** (the store idea, made agent-native):
- **Items** we already have (~200): ~45 sections with ~100 designs, ~50 effects, 9 menus, 5 footers, 11 first screens,
  ~35 signature moments, 6 big ideas, 42 palettes, 58 type pairings.
- **Filters**: job, feel, kind of site, motion level, effect type (hover, scroll, page change, cursor, 3D…), weight,
  "on a real site".
- **Item page**: a clip from a real site, a live demo, its designs, and **"see it in my brand"** — colours, type and
  name set once, the whole library shows in that style.
- **Getting it**: copy as plain code, as a prompt for Claude Code / Cursor (code + where it goes + your tokens), or as a
  registry install (`npx shadcn add opuskit/…`); or add to a cart that checks compatibility and turns into one coherent
  package (the Build Package, born from the cart).
- **What sets it apart from the free libraries**: your brand on everything, a cart that can't make effect soup,
  agent-ready copying, every item checked (no AI-default tells, tokens, reduced motion) with a clean licence, clips from
  real sites.
- **Money**: free to browse, see in your brand and copy most items; Pro for premium items, cart → full package and Site
  Review; later a marketplace where designers sell items.
- **Already built**: SectionPreview (six worlds), PieceDemo, MenuDemo, LinkDemo, DualShot, section designs, the
  compatibility rules in pieces.ts, clips, the Build Package. **To build**: `/library` with filters, item pages, the
  brand switcher, the cart, three copy formats, a registry export.
